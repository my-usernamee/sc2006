# Changes to the supplied code

The original UI, routes, services, schema entities and matching formula were extended in place.

| Area             | Concrete change                                                                                                                                                                                                                                                                                                            |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claims           | Submission, locking, review, report status changes and event notifications run in one serializable transaction. Conditional decisions, bounded retries and partial unique indexes prevent double decisions and simultaneous Pending claims on a report.                                                                    |
| Matching         | Recalculation and notification writes are transactional and batched. Eligibility is separate from numeric score, so rejected pairs never notify at threshold zero while eligible rounded-zero pairs can. Pair notifications have a database uniqueness constraint. Closed/deleted reports are excluded.                    |
| Match navigation | Notification and possible-match links carry the match and lost-report IDs. The protected detail endpoint checks the Lost Item Owner and returns the score with the corresponding found report. Historical unavailable matches cannot be claimed.                                                                           |
| Permissions      | API returns explicit ownership, lock and permitted-action fields. Forms and detail pages hide/disable locked operations, and services independently enforce the same rules. Finder review is explicit rather than inferred from visible fields.                                                                            |
| Deletion         | Authorised Active/Open report deletion hides the report with `deletedAt`. This avoids foreign-key failure after a rejected claim, preserves claim history, and excludes deleted reports from browse, matching and owner lists. Unreferenced photos are removed; historical claim photos remain restricted to participants. |
| Authentication   | Random opaque session cookies are HttpOnly and SameSite=Lax, Secure in production. Only SHA-256 session token hashes are stored. Logout revokes the server session. Browser tokens are no longer kept in local storage.                                                                                                    |
| Location         | Failed or unnamed OneMap results block submission. A signed location selection prevents bypassing lookup with raw coordinates. Stale overlapping map lookups cannot overwrite the latest selection.                                                                                                                        |
| Validation       | Empty/invalid numeric inputs, fractional/out-of-range thresholds, impossible/future dates, invalid dropdowns and missing fields are rejected. Unknown brand is persisted as null.                                                                                                                                          |
| Photos           | Actual image bytes are decoded, JPEG/PNG/WebP accepted, EXIF stripped and WebP stored. Files are limited to 5 MB and 25 million pixels. Failed request uploads and replaced unreferenced files are cleaned up. Photo access requires a session.                                                                            |
| Browser requests | Same-origin cookie requests, request-origin/custom-header checks, no-store API responses, explicit session-expiry handling and protected photo delivery.                                                                                                                                                                   |
| Running          | Root install/dev/build/start scripts, corrected compiled backend path, same-origin SPA serving, migration, Docker image and persistent volumes.                                                                                                                                                                            |
| Verification     | Original matching tests retained. Validation, API/database regression and browser workflow tests added.                                                                                                                                                                                                                    |

No live credentials or real user data are included. Test fixtures are isolated from production code. No Telegram bot, email/SMS service, AI matching service or physical handover tracking was added; these are outside the approved requirements.
